# 输入与输出约定

Python 3.11+；金额全部使用整数人民币分，不能把25元写成25分。时间使用含UTC偏移的ISO 8601，默认业务时区为用户给出的时区；不要把无日期的“12点”默认为今天。

`examples/lunch.request.json` 是可执行的完整例子：

```json
{
  "location": "示例校园教学楼（虚构地点）",
  "start": "2026-10-24T12:00:00+08:00",
  "deadline": "2026-10-24T13:30:00+08:00",
  "budget_cents": 2500,
  "max_walk_minutes": 12,
  "eat_minutes": 15,
  "buffer_minutes": 5,
  "prefer": [],
  "avoid": []
}
```

可选 `available_minutes` 进一步收紧窗口，不会延长deadline。可选 `max_kcal` 是整餐热量硬上限；未知热量被排除。`prefer` 对候选的已核验标签加分，`avoid` 排除冲突候选。标签是Agent核实餐品详情后的解释，并不是完整配料表；过敏需求不应仅凭标签判断。

最短用时 = 单程步行 × 2 + 用户确认的出餐/排队估算 + 用餐分钟 + 缓冲。若返课地点与出发点不同，应增加相应通勤缓冲或不作时间结论。不接入地图或实时排队服务；不会声称任何假设来自实时交通。

三种策略都先过金额、时间、热量、偏好、可售性与有效期硬约束。预算优先按应付金额升序，时间优先按总用时升序；均衡按省预算50%、余量30%、偏好20%评分。范围仅本次最多3店、12完整候选，可能得到相同推荐，不能称全菜单最优。

`demo`只接受mock夹具，`live`只接受本轮真实调用产生的来源映射，不允许从JSON快照直接导入live金额。私人JSON包含门店与精确时间，默认文件权限600。默认HTML分享版只保留餐品名、金额、粗粒度耗时和趣味称号，隐藏位置、门店、精确课程时间、报价原文和券标识；生成在本地，不会自动上传。`--private-details`会显示门店与时间，分享前需要检查。

## ICS

```bash
campus-mcd ics examples/timetable.ics --date 2026-10-24
```

本地解析，不上传ICS内容；仅输出空闲起止时间，不输出课程名/地点。支持TZID、UTC、浮动时间（按`--zone`解释）、单次VEVENT、全天事件、DTEND/DURATION、重叠事件合并；取消事件与TRANSPARENT事件不计为忙碌。默认日间范围08:00–22:00。对RRULE/RDATE/EXDATE及复发实例明确报错，不静默遗漏课程。MVP请先导出已展开的课表日期；文件上限1MB、2000事件。

## 错误

CLI失败以退出码2结束，返回脱敏错误分类。由于校验库可能在原始错误里回显输入，CLI故意不打印原始异常。发现schema后检查本地JSON中的必填字段与单位；401/403检查Token/访问授权；429等待后再运行；超时/断网不采用旧报价。不会在错误后悄悄返回模拟结果。
